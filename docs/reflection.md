# Reflection

## What I learned
Before this lab, I thought GitHub was basically just a place to upload code. Now I see it's more like a whole workspace. Writing the issues first made me stop and think about what the project actually needed before I touched any code, and it made the work feel a lot less overwhelming because I could tackle one small task at a time. I also learned why people use feature branches: I could build something on its own branch, check that it worked, and only then merge it into main, so main always stayed clean. Linking pull requests to issues was my favorite discovery, since the issues closed themselves when the PR merged.

## What was challenging
The terminal was the hardest part for me. At the start I kept forgetting the order of the commands (add, commit, push) and wasn't sure what was happening on my computer versus what was already on GitHub. Pasting into Git Bash also confused me for a bit because the normal shortcut doesn't work there. Another small surprise: I wrote "Closes #1 and #2" in my first pull request, but GitHub only closed the first issue, so I had to close the second one by hand. After that I wrote "Closes #3, closes #4" and it worked properly.

## What was fun
Seeing the page go from a plain white screen to a dark, space-themed page with a working "New Fact" button was really satisfying, even though the app is simple. Clicking Merge and watching the badge turn purple felt great too, and so did seeing my issues close on their own.

## What I would improve with more time
If I had more time, I would pull real facts and the Astronomy Picture of the Day from NASA's API instead of using a fixed list of ten facts. I'd also add categories like planets and missions, make the page look better on phones, and use a GitHub Project board so I could see the whole plan at a glance instead of only a list of issues.
